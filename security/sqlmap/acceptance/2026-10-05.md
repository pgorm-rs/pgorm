## What changed in pgorm

**Identifier quoting was closed at the routes the oracle found.** The
identifier render oracle (`967b4120`) holds every public API that renders a
caller-supplied name to a parse-tree round trip. It found four routes, and
each was fixed:

- A pipeline name beginning with `$`, or a lone `*`, was written bare by
  prqlc, as a bound parameter, a dollar quote or the wildcard. Such names are
  now refused before prqlc runs (`967e9208`).
- `select_sources`' read cast was written verbatim by prqlc. It now goes
  through `TypeName`'s part policy (`c30b42cd`).
- That policy wrote keywords bare, so `Func::named("not")` rendered a boolean
  NOT. It now quotes every keyword PostgreSQL restricts (`8d83e46a`).
- `TypeName`'s verbatim flag was a public field, and savepoint names had a
  route past quoting. Both are closed (`c2e69c41`).

The cases that render a name — `table`, `alias`, `column`, `order`, `group`,
`function`, `schema`, `cast`, `enum`, `enum-ddl`, `graph-alias`,
`pipeline-projection` and `stored-identifier` — exercise the fixed paths.

**The prqlc fork became a dependency.** It had been a `[patch.crates-io]`
table repeated in each manifest. It is now a git dependency that travels with
pgorm into every crate that reaches it (`a9ce44e3`), so the adapter cannot
link stock prqlc by omission. The pipeline cases run against that compiler.

**New constructs landed beside the scanned ones**: sequences, composite and
range types, MERGE, collations, ON CONFLICT ON CONSTRAINT, deferrable
constraints, GROUPING SETS, array subscripts, simple CASE and window frame
offsets. None of them is a case in this manifest. The ones that take a name —
sequences, composite and range types, MERGE, collations, the ON CONFLICT
arbiter and embedded table constraints — each registered their name positions
with the identifier render oracle in the commit that built them.

What this run newly shows is that none of that opened an injection path in a
scanned case. The same 117 controls fire, and the same protected routes stay
clean.

## The attempt that failed

The first full run at this revision, `target/sqlmap-ci/full-1005/`
(03:52–04:30 UTC), detected 116 of 117 controls. It lost `insert-S`. Its
direct regressions passed, no protected route yielded a finding, and no
exemption was falsified.

The control's log shows the stacked-query sleep detected, then lost on
sqlmap's own false-positive check, which re-measures the sleep. The protected
scan that followed reported "considerable lagging has been detected in
connection response(s)". Every response in that minute was slow, not just the
payloads: a connection test took two seconds and the heuristic check six, where
each normally takes milliseconds. `insert-T`, scanned next, passed.

The machine did not sleep: the power log is clear from 2026-10-04 20:22
onwards. The load average read 2.2 at the start and 2.3 at the end, but nothing
sampled it in between. The system log for that minute shows Time Machine's
`backupd` waking at 05:56:03 local and `contactsd` starting a Spotlight reindex
at 05:56:26 — background maintenance that stalls a laptop for a moment. The
failure carries the signature of a host stall, not of a defect, and neither
the control nor the fixture has changed since `insert-S` passed on 2026-09-24. So the run was repeated, this
time with a sampler recording the load average and busiest processes every ten
seconds. The sampler's peak was 4.69, during a desktop app's burst at 04:55,
with no compile running, and every timing control fired.

## What this does not claim

Everything the [2026-09-14 report](2026-09-14.md) declines to claim is declined
here unchanged. That covers the inline-query exemption across all 35 cases and
the standing assumption that some of the 93 exemptions are repairable rather
than structural.

Identifier positions are now split two ways. At this profile's level, six cases
— `schema`, `function`, `column`, `group`, `pipeline-projection` and
`stored-identifier` — still have no scheduled technique, and the full profile
claims nothing about them. The identifiers profile reaches 28 of the 66
identifier pairs at level 5. The other 38 are beyond sqlmap at any level, and
the [2026-10-05 identifiers record](2026-10-05-identifiers.md) lists them. Those
positions belong to the identifier render oracle (`tests/identifier_oracle/`,
`[spec:pgorm:req:security.ident-oracle]`). That instrument, not this one, is
where identifier-injection coverage is claimed.

The timing verdicts carry the caveat the 2026-09-24 report gave. Stacked and
time-based detection confirm by sleeping, so they are only as trustworthy as
the quiet of the host. This run's quiet was sampled, not assumed.
